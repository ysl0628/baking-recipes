# 實驗記錄模板（原版 → 過渡版 → 總整理）

> 使用者的迭代方法論：從「原版」食譜出發，每爐改一個變因做「過渡版」，系列收斂後寫「總整理」。
> AI 的職責：開爐前幫使用者填目標與配方區；收到過程/成品回報後幫填觀察與結論；
> **有價值的通用結論要提案移進對應的 reference 檔**（這份模板是知識進 skill 的入口）。

## 使用原則

1. **一爐只改一個變因**（水合、酵母量、發酵時間、溫度、粉…擇一）——同時改兩個就不知道是誰的功勞。
2. 結論要寫成「**因為觀察到 X，所以判斷 Y**」——沒有觀察依據的結論不落檔。
3. 版本編號：`品項-v0`（原版照做）→ `v1, v2…`（過渡版）→ 收斂後寫總整理。
4. 記錄放 Notion 或本 repo 皆可；**總整理的驗證結論**由 AI 分揀進 skill（照收錄準則：
   通用規則→對應 reference、個人數據→實測區、當下狀態→不落檔）。

| 時刻 | 步驟 | 觀察（照片編號） |
|---|---|---|

## 各站觀察

## 總整理模板（系列收斂後）

```markdown
# 〔品項〕總整理 — v0～v〔N〕（〔起訖日期〕）

## 成功基準配方與流程（最終版全文）

## 驗證過的結論（各附證據爐次）
- 〔結論〕（v2 vs v3 對照）

## 踩雷記錄
- 〔症狀 → 原因 → 對策〕（哪一爐）

## 已移入 skill 的知識點
- 〔條目〕→ 〔哪個檔案哪一節〕
```
